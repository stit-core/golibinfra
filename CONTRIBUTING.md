# Вклад в golibinfra

Это набор инфраструктурных Go-библиотек («кит'ов») для сервисов stit. Вклад
полезен, когда он делает kit'ы чище, надёжнее или удобнее для консьюмера —
наблюдаемость по умолчанию, минимум зависимостей, никакой продуктовой специфики.

## С чего начать

- Прочитай `README.md` (использование, observability, стабильность API,
  версионирование) и `CLAUDE.md` (карта пакетов, инварианты).
- Каждый kit самодостаточен: подключается независимо, экспортирует `Module` для
  fx-проводки. Чтобы понять стиль — посмотри соседний kit рядом с тем, что правишь.

## Принципы

- **Никакой продуктовой специфики.** Если файл знает про конкретные роли, домены,
  имена сервисов — он не здесь, а в сервис-репо. golibinfra — общая lib.
- **Observability by default.** Новый код эмитит метрики/спаны через otel-go SDK,
  читая resource attrs из `telemetry.Config` (не хардкодить).
- **Минимум зависимостей.** Перед новым import проверь stdlib + уже подключённые
  deps. Каждая новая зависимость в `go.mod` обсуждается отдельно.
- **fx-first.** Каждый kit отдаёт `Module` (`fx.Options`); консьюмер собирает `App`
  из них. Прямой `New*()` без fx допустим, но менее идиоматичен.
- **envconfig-теги — часть public API.** Имена полей/тегов публичных конфиг-структур
  (`README.md § Стабильность API`) менять = breaking change, идёт мажорным апгрейдом.
- **Forward-only документация.** Текст описывает текущее состояние, без «было/стало» —
  история живёт в `git log`.

## Форк, issue, PR

- **Issue** — для багов и предложений: что наблюдаешь, как воспроизвести, какой kit
  затронут, ожидаемое поведение.
- **PR** — форкни репозиторий, заведи ветку, открой pull request с понятным описанием
  «зачем». Держи PR сфокусированным; не подмешивай несвязанные правки.
- Менять public конфиг-структуры (имена полей, envconfig-теги, типы) или
  resource-attrs init-флоу — breaking для всех сервисов; такое сначала обсуждается.

## Перед PR

Makefile'а нет — команды сырые `go`, как в CI:

```bash
golangci-lint run ./...           # lint (gofumpt + .golangci.yml)
go test -short -race ./...         # unit (-race при CGO_ENABLED=1)
go build ./...                     # build
```

Зелёные все три — gate пройден.

- Новый kit → строка в `README.md § Пакеты` обязательна.
- Тронул эмитимые метрики/labels/span-attrs → обнови `README.md § Что эмитит каждый пакет`.
- **Conventional Commits** — `<type>(<scope>)?: <subject>`, subject ≤72. Типы:
  `feat`, `fix`, `refactor`, `docs`, `test`, `chore`. Пример: `feat(httpkit): add CSP header`.

## Стиль

Спокойно и по делу, без хайпа. Комментарии в коде — только когда WHY неочевидно,
не пересказ кода. Названия и формулировки — как у соседних пакетов.
