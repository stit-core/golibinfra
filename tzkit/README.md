# tzkit

Календарное время в зоне приложения: резолв IANA-зоны (`Zone`), типы
«календарный день» (`Day`) и «время суток» (`WallTime`) с каноничной
сериализацией, и границы суток, посчитанные в этой зоне.

Kit существует потому, что `timestamptz` решает только половину задачи. Момент
он хранит верно, но на вопросы «какое сегодня число», «просрочено ли»,
«попадает ли в период с 1 по 31 августа» отвечает уже зона — и если её нет,
каждый слой отвечает по-своему: БД в UTC, воркер в зоне процесса, браузер в
зоне устройства. `tzkit` даёт этим слоям один ответ.

## Импорт

```go
import "git.stit.tech/stit-core/golibinfra/tzkit"
```

Версия и `go get` — см. [корневой README § Использование в проекте](../README.md).

## Канон времени

Три разных сущности, которые нельзя смешивать. Это контракт всей экосистемы —
БД, HTTP, шина и UI обязаны совпадать по строке таблицы:

| Сущность | В БД | На проводе | В Go | Пример |
| --- | --- | --- | --- | --- |
| **Момент** | `TIMESTAMPTZ` | RFC3339 в UTC | `time.Time` | `2026-08-08T14:00:00Z` |
| **Календарный день** | `DATE` | `"YYYY-MM-DD"` | `tzkit.Day` | `2026-08-08` |
| **Время суток** | `TIME` | `"HH:MM"` | `tzkit.WallTime` | `17:00` |
| **Окно с зоной** | `TIME` + `TEXT` | пара полей | `WallTime` + `Zone` | `08:00`–`20:00` `Europe/Moscow` |

Правила, которые из этого следуют:

1. **Момент уходит из процесса в UTC.** `.UTC()` на границе HTTP и шины, иначе
   офсет ответа определяется переменной `TZ` контейнера, а не контрактом.
2. **День не ездит как `date-time`.** Поле `format: "date-time"` вынуждает
   клиента прислать момент с офсетом — и день промахивается на сутки. День —
   строка с паттерном; `Day` даёт такую схему huma автоматически.
3. **Границы суток считаются в `Zone`.** `now.UTC().Truncate(24*time.Hour)` —
   это сутки с началом в 00:00 UTC; для `Europe/Moscow` они начинаются в 03:00
   и всё «сегодня» съезжает на три часа.
4. **Зона приложения одна** и приходит из `APP_TZ`. Персональная зона
   пользователя, если появится, подменяет собой `Zone` в точке резолва — все
   вычисления выше от этого не меняются.

## Быстрый старт

Зона приходит из fx и живёт рядом с часами:

```go
fx.New(
	fx.Supply(tzkit.Config{TZ: "Europe/Moscow"}), // обычно — поле app-config
	tzkit.Module,                                 // provide Zone
	clockkit.Module,
	fx.Provide(NewService),
).Run()
```

```go
type Service struct {
	clock clockkit.Clock
	zone  tzkit.Zone
}

// Просрочено ли — вопрос про день, а не про момент: задача со сроком
// «сегодня» просрочена не раньше конца сегодняшних суток.
func (s *Service) Overdue(due tzkit.Day) bool {
	return due.Before(tzkit.DayOf(s.clock.Now(), s.zone))
}

// Период из UI («с 1 по 31 августа») → границы SQL-выборки.
func (s *Service) Report(from, to tzkit.Day) ([]Row, error) {
	start, end := tzkit.Span(from, to, s.zone) // [start, end), to включительно
	return s.repo.Between(start, end)
}
```

DTO объявляют день и время суток своими типами — huma сам опишет их в OpenAPI:

```go
type TaskInput struct {
	Body struct {
		DueDate *tzkit.Day      `json:"due_date,omitempty"` // "2026-08-08"
		DueTime *tzkit.WallTime `json:"due_time,omitempty"` // "17:00"
	}
}
```

Колонки `DATE`/`TIME` читаются и пишутся без промежуточного `time.Time`:

```go
params.DueDate = task.Due.PgDate()          // Day  → pgtype.Date
params.DueTime = tzkit.PgTimePtr(task.At)   // *WallTime → pgtype.Time
task.Due = tzkit.DayFromPg(row.DueDate)     // pgtype.Date → Day
```

## Конфигурация

| Поле | ENV | Дефолт | Смысл |
| --- | --- | --- | --- |
| `Config.TZ` | `APP_TZ` | `Europe/Moscow` | IANA-зона организации |

`Config` kit не провайдит — его регистрирует caller (конвенция golibinfra
≥ v0.17). `NewZone` возвращает ошибку на пустом имени, на неизвестной зоне и на
`"Local"`; во fx это отказ старта.

`"Local"` запрещена намеренно: она резолвится в `TZ` процесса, то есть
возвращает ту самую зависимость от окружения контейнера, ради устранения
которой kit и нужен.

## Observability

Кит ничего не эмитит — ни метрик, ни спанов, ни логов, и не зависит от OTel.
Это чистый примитив над `time`.

## API

### `Zone`

| Метод | Что |
| --- | --- |
| `Load(name) (Zone, error)` / `MustLoad(name)` | резолв IANA-имени |
| `UTC() Zone` | зона UTC явным значением |
| `NewZone(Config) (Zone, error)` | fx-фабрика |
| `Name() string` / `Location() *time.Location` | имя и `*time.Location` |
| `In(t) time.Time` | тот же момент в этой зоне |
| `OffsetAt(t) time.Duration` | смещение от UTC в конкретный момент |
| `IsZero() bool` | зона не резолвлена (ведёт себя как UTC) |

### `Day`

| Метод | Что |
| --- | --- |
| `NewDay(y, m, d)` | конструктор, нормализует переполнение как `time.Date` |
| `DayOf(t, z) Day` | день, на который приходится момент в зоне `z` |
| `ParseDay(s) (Day, error)` | строгий разбор `"2006-01-02"` |
| `Start(z)` / `End(z)` | полночь дня и начало следующего — полуинтервал `[Start, End)` |
| `At(w, z) time.Time` | момент времени суток `w` в этом дне |
| `AddDays(n)` / `DaysUntil(o)` | календарная арифметика |
| `Before` / `After` / `Equal` / `Compare` | сравнение |
| `Weekday()` | день недели (от зоны не зависит) |
| `String()` / JSON / текст | `"2026-08-08"`; нулевой день — `""` и `null` |
| `PgDate()` / `DayFromPg(v)` | колонка `DATE` |

### `WallTime`

| Метод | Что |
| --- | --- |
| `NewWallTime(h, m)` / `ParseWallTime(s)` | конструкторы; строгий формат `"15:04"` |
| `Hour()` / `Minute()` / `Duration()` | разбор |
| `Valid()` | значение в пределах суток |
| `String()` / JSON / текст | `"17:00"` |
| `PgTime()` / `WallTimeFromPg(v)` | колонка `TIME` |

### Свободные функции

| Функция | Что |
| --- | --- |
| `StartOfDay(t, z)` | начало суток, в которые попадает момент |
| `Span(from, to, z)` | `[from.Start(z), to.End(z))` — период дней в границах моментов |
| `PgDatePtr` / `DayPtrFromPg` / `PgTimePtr` / `WallTimePtrFromPg` | nullable-варианты |

## Тестирование

`Zone` детерминирована сама по себе — фейков не нужно, в тесте берётся
`tzkit.MustLoad("Europe/Moscow")`. Недетерминированная часть — часы, их даёт
`clockkit.NewFixed`. Пара этих двух делает тест независимым и от часа, и от
зоны прогона:

```go
zone := tzkit.MustLoad("Europe/Moscow")
clock := clockkit.NewFixed(tzkit.NewDay(2026, time.August, 8).At(mustWall("09:00"), zone))
```

Фиксировать только `time.Now()`, оставив зону на усмотрение раннера, —
типичная ошибка: тест зелёный локально и красный в CI, где `TZ=UTC`.

## Инварианты и подводные камни

- **`Day` — не момент.** У него нет времени и нет зоны. Любое сравнение с
  `time.Time` идёт либо через `Start`/`End`/`At`, либо через `DayOf` в обратную
  сторону. Прямой `time.Parse("2006-01-02", s)` даёт полночь UTC — для зоны
  восточнее это предыдущий день, для западнее следующий.
- **Нулевой `Day` — «не задан», нулевой `WallTime` — полночь.** У дня есть
  осмысленный признак отсутствия (`IsZero`, `null` в JSON), у времени суток нет:
  `00:00` — валидное значение, поэтому необязательное поле — только `*WallTime`.
- **`AddDays` двигает календарь, а не 24 часа.** В сутки перевода стрелок
  `Start` соседних дней отстоят на 23 или 25 часов, но день — следующий.
  Прибавление `24*time.Hour` в такой зоне ломает еженедельную встречу.
- **`Start` в зоне, где полночи не существует.** В зонах, переводящих стрелки в
  00:00, `time.Date` нормализует момент вперёд — это корректная первая точка
  суток, но она не равна «00:00».
- **`PgDate`/`DayFromPg` читают календарные поля, а не переводят зону.** pgx
  кодирует `DATE` по `Y/M/D` самого `time.Time`; прогон значения через
  `.UTC()` или `.In(loc)` перед записью сдвинет дату. Момент превращается в
  день только через `DayOf` с явной зоной.
- **Границы периода — полуинтервал.** `Span` отдаёт `[start, end)` с
  включительным `to`; в SQL это `>= start AND < end`. `BETWEEN` по моментам
  захватит лишнюю точку.
- **tzdata вшита в бинарь** (`_ "time/tzdata"` внутри кита): рантайм-образы
  сервисов — alpine без пакета tzdata, а `CGO_ENABLED=0` отключает системный
  резолв зон. Отдельный импорт в `main.go` больше не нужен.
- **Зона одна на приложение.** Kit не знает про пользователей: если появится
  персональная зона, она подменяет `Zone` в точке резолва, а вся арифметика
  выше остаётся прежней.
