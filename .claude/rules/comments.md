# Комментарии

Правило делит комментарии надвое.

**Doc-comment на экспортируемом идентификаторе — обязателен** (Go-конвенция, `revive.exported` в гейте): одна строка, начинается с имени идентификатора, говорит, что это и чего от него ждать. Это контракт для `go doc` потребителя, а не «нарратив». Больше одной строки уместно, только когда контракт того требует: набор исходов/сентинелов, что обязан положить в граф caller, ограничение, о котором иначе узнают в проде. Package-doc — 1–3 строки: что за пакет и какие сигналы эмитит; детали — в `README.md` кита.

**Всё остальное — по умолчанию не писать.** Внутри функций хорошее имя уже объясняет WHAT. Комментарий допустим, только если без него читатель не догадается о **WHY** — скрытая инварианта, неочевидное ограничение, workaround под конкретный баг, поведение которое удивит.

## Запрещено

- **Restate WHAT.** `// GetUserByID возвращает пользователя по id` над `GetUserByID` — формально doc-comment, но пустой: скажи, что бывает при отсутствии (`ErrNotFound`), или ничего сверх имени.
- **Narration.** Многострочный пересказ "сначала делаем X, потом Y, наконец Z". Код это и так показывает.
- **Архитектурные эссе в package docstring.** Не описывай pattern/принципы рядом с реализацией — это место для `README.md` или `CLAUDE.md`. Особенно касается `package module` файлов.
- **Tombstones.** `// removed XXX`, `// was using Y before` — нет, для этого есть git log.
- **Reference to current task/PR.** `// added for X flow`, `// fix for issue #123` — это в commit message / PR description, не в коде.
- **Flavor commentary.** Художественный пересказ того, что и так видно.
- **TODO без контекста.** `// TODO: fix this` — бесполезно. Оставляешь TODO — дай ticket/owner/condition.
- **Section dividers.** `// ===== Helpers =====` — Go-файлы и так структурированы.

## Допустимо внутри функции (одна короткая строка)

- WHY-инвариант: `// Алиас, а не новый тип: X структурно удовлетворяет Y.`
- Workaround: `// pgx отдаёт jsonb как []byte; приводим сами до фикса в v5.7.`
- Сюрпризное поведение: `// Вызывать до Start: здесь регистрируются хендлеры в fx-графе.`
- Хитрая константа: `// 90s = idle-таймаут upstream nginx − 10s запаса.`

## Чек

Комментарий внутри функции длиннее **одной строки** — почти наверняка лишний: вырази именем/структурой, а «почему так» — в `README.md`, не в `.go`. Doc-comment длиннее одной строки — проверь, что каждая следующая строка добавляет контракт (исход, требование к графу, ограничение), а не пересказ. После правки глянь diff: добавленный комментарий объясняет невидимое из кода? Нет — удали.
