# Форма плана

Файл `.claude/plans/<slug>.md`. Slug — `<глагол>-<объект>[-<уточнение>]`, kebab-case, 2–4 слова,
без даты; у фазы программы — slug программы. Текст в угловых скобках — подсказка, в план он не
переносится.

```markdown
---
status: planning
parent: —
blocked-by: —
---

# <slug> — <понятный заголовок>

## Цель
<1–3 предложения: какой результат, для кого и зачем сейчас.>

## Контекст
<Что нужно, чтобы продолжить с нуля: код (`path:line`), `docs/`, stable-артефакты `<org>/strategy`,
связанные планы и программа хаба, ограничения, что уже известно.>

## Не входит
- <что осознанно не делаем>

## Критерии приёмки
- [ ] **AC1** — <наблюдаемый результат>. Проверка: `<команда>` → <ожидаемый итог>
- [ ] **AC2** — <…>. Проверка: <ручная проверка: что открыть и что должно быть видно>

## Шаги
- [ ] **S1** — <результат шага>
  - Проверка: `<команда>` → <итог> · Закрывает: AC1 · Зависит от: —
- [ ] **S2** — <…>
  - Проверка: `<гейт репо>` → зелёный · Закрывает: AC2 · Зависит от: S1

## Решения
- <решение> — <почему>

## Открытые вопросы
- [ ] **Q1** — <вопрос> — блокирует: S2 — к кому: <пользователь / владелец / архитектор>

## Handoff
—

## Где мы сейчас
<Что сделано последним, что обнаружено, какой следующий шаг.>
```

Закрытые пункты выглядят так:

```markdown
- [x] **AC1** — <…>. Проверка: `make test` → PASS
  - Подтверждено: `make test` → PASS
- [x] **S1** — <…>
  - Проверка: `make test` → PASS · Закрывает: AC1
  - Сделано: <результат: что появилось>; `make test` → PASS
```

Необязательные разделы (`Не входит`, `Решения`, `Открытые вопросы`, `Handoff`) без содержания
удаляй или оставляй с `—`. Большой план делится на этапы заголовками `### <этап>` внутри «Шагов».

## Хороший критерий приёмки

- Проверяем снаружи: «`POST /api/auth/register` с занятым адресом возвращает 409», а не «регистрация
  реализована».
- Называет проверку и ожидаемый итог. Ручная проверка — тоже проверка, если сказано, куда смотреть.
- Про результат, а не про путь: «гейт зелёный» — это последний шаг, а не критерий, если задача не
  про сам гейт.
- Всё обещанное в «Цели» проверяется хотя бы одним критерием; всё, что не обещано, — в «Не входит».

## Хороший шаг

- Один коммит работы с понятным результатом и проверкой, которую можно прогнать сразу.
- Закрывает критерии или готовит почву для шага, который их закрывает.
- Не расписывает «как»: исполнитель выбирает способ по ходу и фиксирует нетривиальное в «Решениях».
