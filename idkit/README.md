# idkit

Генерация внутренних идентификаторов. `NewV7` отдаёт UUID v7 (RFC 9562) строкой —
time-sortable id, у которого старшие биты несут unix-ms. В отличие от случайного
v4, такие id монотонно растут во времени и дают локальность в B-tree индексах
(меньше фрагментации страниц для PK). Без зависимостей сверх `google/uuid` и без I/O.

## Импорт

```go
import "git.stit.tech/stit-core/golibinfra/idkit"
```

Версия и `go get` — см. [корневой README § Использование в проекте](../README.md).

## Быстрый старт

```go
id := idkit.NewV7() // "0190e8a1-... " — uuid v7 строкой

// Как production-seam для конструктора, принимающего IDGen func() string:
mirror, err := domain.NewEntity(accountID, snap, idkit.NewV7)
```

Точная сигнатура:

```go
func NewV7() string
```

## Observability

Кит **ничего не эмитит**: ни метрик, ни спанов, ни логов.

## Инварианты и подводные камни

- **Time-sortable только между миллисекундами.** Старшие 48 бит — unix-ms; внутри
  одной миллисекунды хвост случаен, поэтому строгий порядок гарантирован лишь для
  id, сгенерированных в разные мс. Для PK-локальности этого достаточно.
- **Паника при отказе `crypto/rand`.** `NewV7` оборачивает `uuid.NewV7` в `Must`:
  ошибка генератора случайности — невосстановимое состояние процесса, не business-кейс.
  Поэтому сигнатура — `func() string`, удобная как seam без проверки ошибки.
- **Только v7.** Нужен v4/иной — бери `google/uuid` напрямую; idkit намеренно
  узкий (один производственный выбор id для сервисов stit).
